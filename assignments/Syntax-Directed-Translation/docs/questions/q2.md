# Q2 Inherited Declaration Types

### Shared SDD and Student A information flow

```text
D → T L         L.in := T.type
T → int         T.type := int
T → float       T.type := float
L → L₁ , id     L₁.in := L.in; after L₁: addType(id.entry, L.in)
L → id          addType(id.entry, L.in)
```

```text
D
├─ T.type = float ─────────────────────▶ L₀.in = float
│  └─ float                               ├─ L₁.in = float ◀─ L₀.in
│                                         │  ├─ L₂.in = float ◀─ L₁.in
│                                         │  │  └─ id(a) → addType(a,float)
│                                         │  ├─ ,
│                                         │  └─ id(b) → addType(b,float)
│                                         ├─ ,
│                                         └─ id(c) → addType(c,float)
```

The list subtree does not contain its type. For the same list a,b,c, changing float to int leaves the list subtree identical, so L.in cannot be obtained from children alone. Compute T.type, pass it to the sibling list and down its spine, then register a, b, c in source order.

Right recursion can use L → id R; R → , id R₁ | ε. Register each id with the current inherited type, pass L.in to R.in and R.in to R₁.in before descending; ε does nothing. The left-recursive form descends to the first name before inserting; the right-recursive form can insert as it reads each name.

| Input | Observed status | Symbol table after the attempt |
| --- | --- | --- |
| float a,b,c; | Accepted | a:float, b:float, c:float |
| int x,y; | Accepted | x:int, y:int |
| int a,a; | Duplicate a | a:int (first binding kept) |
| float a,; | Syntax error | Empty (no actions after failed parse) |

### Student B comparison and joint redesign

| Attribute | Direction | Best use |
| --- | --- | --- |
| Synthesized | Child to parent | Expression value; list of identifier entries |
| Inherited | Parent or left sibling to child | A declaration type shared by its names |

Alternatively synthesize a list of names and install them at D using T.type. This delays updates and stores the list; inherited flow can install earlier. Reading a missing value before its dependencies run would give an undefined or wrong type. addType rejects a duplicate in the same scope; lookup rejects an undeclared use. For int a, float b; use Item → T id with a local addType(id.entry,T.type), so the list needs no inherited type.
