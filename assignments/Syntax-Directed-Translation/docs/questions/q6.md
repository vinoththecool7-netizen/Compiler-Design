# Q6 LR Markers and Three Address Code

### Student A inherited types on an LR stack

The original grammar reduces L → id before D → T L, so computing L.in in D’s reduction is too late for L’s action. An empty marker stores the context before the list is reduced: D → T M L; M → ε copies the T.type immediately below; L → id takes M.type immediately below id; L → L₁ , id reuses L₁.type.

```text
reduce M -> epsilon       [T:int] -> [T M:int]
reduce L -> id            [T M id:x] -> [T M L:int]
reduce L -> L , id        [T M L , id:y] -> [T M L:int]
reduce D -> T M L         [T M L:int] -> [D]
```

At M reduction, the RHS is empty, so Bison’s $0 denotes T at the stack top. At the first L reduction, M is one symbol below id. The Bison action reads its semantic value as $0, the entry immediately before the RHS. Later reductions use L₁ in the RHS. The fixed-offset technique fails when one shared production can be reached with different prefix layouts. Erasing M from any derivation gives an original derivation and inserting ε after T reconstructs it. The marker preserves the grammar’s language but can introduce LR conflicts by requiring an earlier reduction.

### Student B synthesized addresses and code

```text
E → id          E.addr := id.lexeme; E.code := ε
E → E₁ op E₂    E.addr := newTemp();
                E.code := E₁.code || E₂.code || (E.addr = E₁.addr op E₂.addr)
S → id = E      S.code := E.code || (id.lexeme = E.addr)
```

Use + and * in the binary schema, and extend it to − and /. The precedence grammar from Q1 fixes grouping. newTemp allocates t1, t2, … once per binary action. The C harness lowers the checked postfix sequence for x = a + b * c − d to the following TAC.

```text
t1 = b * c
t2 = a + t1
t3 = t2 - d
x = t3
```

```text
S → if ( B ) S₁ else S₂
B.true := fresh(); B.false := fresh(); S₁.next := S.next; S₂.next := S.next
S.code := B.code || label(B.true) || S₁.code || goto(S.next)
          || label(B.false) || S₂.code
B → E₁ rel E₂
B.code := E₁.code || E₂.code || if_rel_goto(B.true) || goto(B.false)
```

The surrounding control structure chooses branch and continuation labels; B consumes them and emits its tests. In this layout, the enclosing statement emits S.next after the construct. Labels could instead be synthesized as unresolved jump lists and patched later. Concatenation order matters: operand code must define a temporary before its use, and the jump over else must appear before the else label.
